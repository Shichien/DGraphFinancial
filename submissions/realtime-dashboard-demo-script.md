# 智鉴流盾实时大屏视频演示流程与讲稿

## 使用场景

这份脚本用于录制主前端演示视频，建议成片时长控制在 3 分钟左右。演示重点不是逐个介绍按钮，而是展示交易进入、风险识别、告警生成、团伙追溯、人工复核和审计留痕这一条完整闭环。

演示入口：

```text
http://127.0.0.1:8060
```

录制前建议先确认：

- 后端实时服务已启动，页面顶部 Kafka 吞吐和 Flink 延迟有数值。
- 页面处于浅色主题，缩放比例为 100%。
- 从总览页开始录制，左侧导航可见。
- 如需自动走主流程，可以点击顶部演示按钮；如需更稳的节奏，也可以按下面的时间点手动点击页面。

## 三分钟版本

各位评委老师好，现在我们展示的是智鉴流盾——实时反诈平台的主前端。我们的系统把仿真交易流、实时评分、告警处置和团伙追溯集中在一个工作台里，能提供在线识别和人工复核。总览页是值班人员的第一视角，它同时展示当前交易关系图、最近交易、风险解释和系统状态。通过这个页面可以快速判断交易流是否正常进入、风险事件是否持续出现，以及当前最高风险节点的判定依据。

交易进入系统后，前端会持续接收最新快照。左侧图谱展示当前窗口内的账户和关系，右侧交易监测展示最新交易，风险解释区会把当前节点的风险分、风险等级和主要证据同步展示出来。

每一笔交易都会结合账户历史风险、实时行为变化、团伙关系和规则命中得到综合风险分。我们不仅适配了金融欺诈领域知名的 DGraph-Fin 数据集，还适配了多个 Kaggle 竞赛中的金融欺诈数据集，以证明我们系统的强适配性

为了更清楚地展示主链路，我们启动内置演示流程。它会按真实风控处理顺序依次切换页面，从实时进件开始，一直到复核结果写入审计链路。

当风险分达到中高危等级后，事件会进入告警工作台。告警页承担风险事件分拣功能，表格中的每一行代表一条已评分交易，字段包括时间、等级、风险分、账户链路、渠道、命中剧本、团伙和处置状态。这里可以按等级、渠道、欺诈剧本、团伙编号和处置状态筛选，把高优先级事件从实时流中快速挑出来。

选中告警后，右侧立即给出案件摘要，包括风险分、账户链路、交易金额、命中剧本和处置建议。这个界面能让人员先判断优先级和处理方向。

进入案件页后，可以看到单个风险事件的证据链。案件页承担证据汇总功能，它把交易本身、关联路径、评分拆解、团伙关系和原因码放到同一页，避免复核人员只看到一个风险分却不知道原因。系统不仅展示源账户和目标账户，还会列出关联路径、评分拆解、团伙编号、共用设备账户数、同 IP 账户数和原因码，帮助复核人员理解为什么这笔交易被判为高风险。

评分解释把最终风险分拆成几类贡献。离线模型提供账户风险先验，实时行为反映交易突增和金额异常，团伙关系来自图邻域证据，规则分则对应黑名单、设备复用、商户异常等明确命中项。

对反诈来说，单笔交易往往不够。图追溯页承担关系扩展功能，它把资金路径和设备、IP、商户等非资金关系合并展示，并支持按欺诈模式过滤。我们可以从一个告警节点扩展到完整团伙子图，判断它是孤立风险，还是处在协同行为中。

这里可以按不同风险模式过滤关系，例如设备复用、IP 聚集和商户洗钱。选中团伙后，图谱会聚焦相关节点，右侧同步展示成员数量、总金额、最高风险分和命中剧本。

当定位到账户节点后，系统会查询完整邻域，展示一跳和二跳相关关系。资金路径、共同设备、共同 IP 和商户关系会用不同样式区分，这让处置人员能沿着证据链继续追查。

控制台页承担演示和联调功能，用于构造测试交易流。我们可以选择低风险单笔、设备复用批次、商户洗钱批次或跨渠道混合场景，直接生成一组交易并提交给评分链路，提交后直接观察模型输出、原因码和实时特征，用来验证系统对不同欺诈模式的响应。

运行后，右侧会展示本次评分结果，包括每条交易的风险等级、风险分、处置建议和原因码。选中单条结果，还能看到设备、IP、商户、团伙编号以及实时特征，方便检查模型输出是否符合业务预期。

告警进入复核页后，复核页承担人工处置功能。待办列表展示需要处理的高风险案件，当前案件区域给出关键信息，风控人员可以选择当前案件，并执行确认欺诈、人工冻结或误报放行。这个动作会写入案件记录和审计日志，形成从模型识别到人工处置的闭环。

处置完成后，页面会显示最新处置记录，同时审计链路保留风险判定和人工处置日志。这样后续无论是复盘、申诉还是模型回灌，都有可追溯依据。

运行页承担运行观测功能，用于观察平台持续处理能力。它展示最近一分钟趋势、风险统计、欺诈剧本、风险节点排行和交易监测。这里还能看到吞吐、延迟、告警数量和模型耗时，证明前端展示的是一个持续运行的实时系统。

最后看整体架构。架构页承担整体说明功能，它把仿真接入、消息总线、流式计算、图状态服务、模型评分、告警输出、存储缓存、前端展示和训练反馈闭环放在一张图里。交易从仿真器进入消息队列，经过流式计算生成实时特征，再由评分服务、图状态服务和存储组件共同支撑前端展示，人工复核结果最终回到审计和训练反馈链路。
